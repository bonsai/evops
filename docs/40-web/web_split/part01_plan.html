検討項目 3 / 10

Java か、Python か？言語は手段。採用理由と不採用理由の両方を書く。

06
結論採用言語

Python 3.13 を採用する。

採用理由
  • bpy ネイティブで Blender と統合できる。
  • MCP server 群（db / evaluator / blender-bpy）が Python で実装済み。
  • VLM クライアント・FastMCP が PyPI で利用可能。
  • SVG 生成・シーケンス描画に標準ライブラリ（svgwrite）が使える。
Java を採用しなかった理由
  • bpy のメインベースが Python。JNI 経由だと遅延が高い。
  • VLM クライアント・ML ライブラリ（scikit-learn / sentence-transformers）が Python 環境で完結。
  • 1 人の開発スピードを優先し、言語統一で構成を簡潔にする。

システムの全体像（自然語＋図）外部システム・ハードウェアとの入出力まで含める。

07
自然語4 段落

本システムは AI評価・修復ループ である。主要な利用者は AI画像生成クリエイター であり、利用者は 思い通りの画像を作れない と困っている。システムは プロンプト調整なしで最適画像を生成 を行う。

構成要素は MCP server 3 基（db / evaluator / blender-bpy） からなる。VLM 評価 が中心となる。

データは SQLite に永続化される。ループ回数と画像品質の相関 である。

他のシステムとの関係は MCP stdio 接続で連携 である。

前提・制約
  • 動作環境：CPU 16GB（GPU なし）
  • 入力：プロンプト（自然言語）
  • 出力：SVG／PNG 画像
  • 制約：Blender MCP + bpy（CPU レンダリング）
  • 対象外：GPU マシン・リアルタイムレンダリング
既存手段との比較
手段良い点不足点
手作業完全に手動で調整可能試行回数が無制限・コストが高い
既存ソフト即座に利用可能プロンプト調整に依存・品質にばらつき
