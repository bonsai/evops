分析モデルと設計モデルの違い：分析は「何をするか」（開発者の言語・問題領域由来・実装非依存）。 設計は「どう実装するか」（言語依存・動的・クラス図中心）。同じ図形でも中身が変わる。
納品物 3 — 設計モデル

設計モデル：パッケージ構成先に層を決める。依存方向を 1 つに固定する。

18
FIG 3-1
パッケージ構成図
図 3-1　パッケージ構成（矢印は呼び出し方向。依存は外向きのみにする）
実装順（下から）
  1. domain：エンティティだけ。単体でテストできる。
  2. repository：永続化の読み書き。
  3. service：ユースケース 1 本ずつ。
  4. ui：最後に画面を載せる。
禁止する依存
  • domain から ui を参照しない。
  • service が ui のクラスを生成しない。
  • 画面サイズなど UI の都合を domain に持ち込まない。
コーディング規約
  • 関数・変数は snake_case／クラスは PascalCase
  • 1 ファイル 1 クラス（main.py を除く）
  • 公開関数には docstring を書く
納品物 3 — 設計モデル

設計モデル：クラス図属性・操作・関連まで書く。これが実装の土台になる。

19
FIG 3-2
クラス図
図 3-2　クラス図　／　「──」＝関連、「▷」＝実現（interface）、「△」＝継承
必ず書く
  • 可視性（＋／−）
  • 型（: int／: str）
  • 多重度（1／0..*）
属性の private 化
  • 属性は原則 −
  • 外部からは getter 経由
  • 変更できないものは read-only
分析モデルとの差
  • 操作のシグネチャを書く
  • «interface» が現れる
  • 実装言語の型が入る
