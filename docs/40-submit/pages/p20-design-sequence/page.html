図 3-3　メッセージ名は設計契約を示す。具体的なシグネチャは実装時に一致させる。
メッセージ契約
要求GenerationRequest：prompt、model/workflow、seed、size、output options
生成ポートGenerationPort.generate(request) → artifact reference または構造化エラー
実行記録GenerationRun：execution_id、status、timestamps、error_code、retryable
成果物Artifact：artifact_id、uri、media_type、metadata
状態・例外・設計上の制約
  • 状態遷移：queued → running → succeeded / failed。不正な遷移は拒否する。
  • 入力検証失敗はエンジンを呼ぶ前に返し、理由をUIに表示する。
  • エンジン失敗と成果物保存失敗は別のエラーとして記録する。
  • Repositoryは保存手段を隠蔽し、Serviceは具体的なJSON／DB実装に依存しない。
  • 再試行では同じ実行IDを曖昧に上書きせず、試行と成果物の対応を追跡可能にする。
設計判断：これはp19のクラス責務に対応する論理シーケンス図であり、API名・保存方式の確定図ではない。実装と異なるメソッド名は実装PRで同期する。
