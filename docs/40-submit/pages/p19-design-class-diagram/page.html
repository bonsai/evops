p19 設計モデル：クラス図

p18のパッケージ構成を、画像生成UC1の主要クラスと契約に具体化する。

19

主要クラスと依存関係

責務と不変条件

  • Request：生成条件を保持し事前検証
  • Service：実行ID、呼び出し、状態確定を調整
  • Run：実行状態と計測情報を保持
  • Artifact：成果物URI・形式・検証情報を保持

インターフェース境界

  • GenerationPort：モデル固有APIを共通化
  • RunRepository：履歴の保存・取得・イベント追記
  • 具体adapterは起動時に注入
  • 失敗を成功状態として保存しない

契約とテスト

観点契約テスト
入力検証不正条件ではエンジンを呼ばない必須項目・境界値
状態遷移queued → running → succeeded / failed不正遷移を拒否
永続化execution_idで実行を追跡保存・取得・重複防止
交換可能性interface経由でエンジンを呼ぶfake adapterで単体テスト
注記：本図は設計候補。最終的な型名、同期／非同期API、DBスキーマは実装IssueとADRで確定する。
