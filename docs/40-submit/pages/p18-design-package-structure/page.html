パッケージ構成図

図は論理パッケージを示す。repositoryの具体実装をdomainから直接参照させず、serviceが定義済みポートを介して利用する。

責務

  • ui：入力・表示・コマンド受付
  • service：UCの手順・状態遷移・調整
  • domain：値・不変条件・業務規則
  • repository：永続化と外部I/O

依存ルール

  • UIはserviceの公開ユースケースを呼ぶ
  • domainはUIや外部SDKを知らない
  • serviceはrepositoryの抽象ポートに依存する
  • 具体adapterは起動時に注入する

実装・テスト順

  1. domainの型と不変条件
  2. repositoryポートと保存テスト
  3. serviceの正常・例外系
  4. UI / CLI / MCP adapter

実行ID・状態遷移・調整service / domain正常系・失敗系を単体テストできる
