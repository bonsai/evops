# 評価ループと統計データの蓄積

## 先生案

> プロンプト・生成物・評価データを **すべてコンテキストで与え直して** 再生成を繰り返す。

### メリット

- 履歴を全部覚えていれば、失敗パターンや成功パターンを引き継げる
- プロンプトの修正履歴が文脈に残る

### デメリット

- コンテキストが肥大化し、コスト・レイテンシーが増大
- 同じ失敗を繰り返す可能性
- 外部サービスに依存し続ける

## 自分案：DB / ナレッジベース化

先生案をベースに、以下を永続化して再利用する。

```text
[生成] → [評価] → [DB 保存] → [検索/要約] → [次の生成に反映]
```

### 保存するデータ

| テーブル/コレクション | 内容 |
|----------------------|------|
| `prompts` | プロンプト、パラメータ、バージョン |
| `generated_items` | 生成物へのパス、メタデータ、派生元プロンプト |
| `evaluations` | 人間 or 機械によるスコア、コメント、タグ |
| `feedback` | 再生成指示、修正点、採用/不採用 |
| `knowledge` | 抽出された成功/失敗パターン、ルール、類似度情報 |

### 技術候補

- **SQLite**: ローカル、軽量、構造化データ向け
- **PostgreSQL**: 中規模、JSONB で柔軟に
- **ベクトル DB (ChromaDB, Weaviate, pgvector)**: 生成物の特徴量やプロンプトの意味検索

## 評価ループの流れ

```text
1. 初期プロンプト p0 を作成
2. 生成物 g0 を作成
3. 評価 e0 を実施（人間 or 自動スコア）
4. (p0, g0, e0) を DB に保存
5. 過去の知見 k を DB から検索
6. 新プロンプト p1 = improve(p0, e0, k)
7. g1 を生成
8. ループ
```

## 評価指標（画像）

| 指標 | 方法 | 備考 |
|------|------|------|
| 美的スコア | 人間評価 1-5 | 最も信頼できる |
| テーマ適合度 | 人間 or CLIP 類似度 | コンセプトとの一致 |
| 多様性 | FID、LPIPS、embedding 分散 | 似すぎ防止 |
| 技術品質 | 解像度、ノイズ、崩壊検出 | 自動化しやすい |
| ターゲット反応 | A/B テスト or 模拟 | ポートフォリオ評価用 |
