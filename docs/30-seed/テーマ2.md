# SSSS Research Theme 2 — 3D 生成の VLM 評価→ML 学習→自動修復ループ

## テーマ

**「pain（ストレス）をなくす」を実現する自律改善型 3D 生成ループ。**
テーマ 1 が 2D（SVG/CSS）ベースであるのに対し、テーマ 2 は 3D（Blender/bpy）を
生成対象とし、VLM 評価と ML 学習によって「人間が修正するストレス」を
コードレベルまで自動軽減する。

## 初期プロンプト（起点）

ドラえもん（青い猫型ロボット）の Blender 造型。
- 青い体・白い顔とお腹・黄色い首輪・赤い鼻と鈴・黒い目・白の手袋・赤い靴・尻尾
- 原型は bpy プリミティブ（sphere/cylinder/torus）で組む

## 全体構成

```
Intent（プロンプト）
  ↓
Generate      — bpy で 3D 造型コードを生成
  ↓
Render        — Blender でレンダリング（CYCLES）
  ↓
VLM 評価       — LMS/LLM/VLM が画像を判定：recognizable? / 不足 / 誤り
  ↓
DB 蓄積       — intent, code, render, evaluation JSON を構造化蓄積
  ↓
ML 学習        — bqmlite でスコアと改造項の相関を学習（mean / linear_regression / logistic_regression）
  ↓
Repair         — VLM の repair instruction を元に bpy コードを自動修正
  ↓
Regenerate    — 1 へ戻る（スコアが上限になるまで）
```

## 各レイヤー

| レイヤー | 担当 | 技術 |
|---|---|---|
| 生成 | bpy コード生成・編集 | Blender/bpy |
| レンダリング | 画像生成 | Blender (CYCLES, Eevee) |
| 評価 | semantic/perceptual 判定、failure 分析、repair instruction | LMS/LLM/VLM（LM Studio ローカル VLM） |
| 蓄積 | 評価履歴・失败・修正履歴の構造化保存 | SQLite / JSONL |
| 学習 | スコア・特徴・スコア改善の相関・予測・repair 優先度 | bqmlite（決定論的・SHA-256 fingerprint） |
| 可視化 | ループ履歴の分析・ダッシュボード | matplotlib, pandas, numpy, plotly, PyVista（3D メッシュ可視化） |
| エージェント連携 | MCP 経由の A2A（agent-to-agent）通信 | MCP サーバ（bpy/Blender, bqmlite, LM Studio） |
| コード管理 | bpy コード差分の管理・レビュー | GitHub（git diff）、diff reviewer |
| オーケストレーション | ループ制御・エージェント連携 | LangChain 3 兄弟（LangChain / LangGraph / LangSmith） |

## LangChain 3 兄弟の役割

- **LangChain** — プロンプト管理、ツール呼び出しの標準フレームワーク
- **LangGraph** — 評価→学習→修復のループを「状態機械」として実装（循環・分岐の可視化・制御）
- **LangSmith** — 各ターン（生成・評価・学習・修復）のトレーシング・モニタリング・評価指標の可視化

SF 小説執筆（テーマ 1 の延長）でも LangChain 3 兄弟をエージェント連携に使う。

## PyVista の活用

生成された 3D メッシュ（bpy 造型結果）をプログラムから直接可視化：
- メッシュのメトリクス可視化（ポリゴン数、法線、バウンディングボックス）
- ループごとの形状変化の比較
- matplotlib/plotly と併せて分析ダッシュボードへ統合

## bqmlite の役割

- ループ履歴（obj_count, has_bell 等の改造項 × VLM スコア）を学習
- 次の修復で効果的な改造を rank / predict
- 決定論的（SHA-256 fingerprint）なので再現性保証
- MCP サーバとしてエージェントに公開

## GitHub 上の bpy diff

- bpy コードは GitHub リポジトリでバージョン管理
- 各ループごとの code diff を自動的に収集・保存
- diff 内容（「鈴を追加」等）を VLM の評価と対応させてデータセット化

## 研究目標

1. VLM を評価器として使い、生成結果・評価・失敗・修正履歴を DB に蓄積できるか
2. 蓄積履歴から ML（bqmlite）で次の生成・修復戦略を改善できるか
3. MCP で統合した A2A アーキで、人間介入を最小化できるか
4. 可視化（matplotlib/pandas/numpy/plotly/PyVista）で改善プロセスを言語化できるか
