# ドラえもん VLM 修正ループ：評価軸・可視化・人間介入

> ⚠️ 著作権上の注意：ドラえもんは藤子プロ・小学館等の著作物である。本ドキュメントは「既存キャラクターの意図をどう VLM で検証・修正するか」という技術設計の例示であり、実際の生成・公開には権利者の許諾が必要。卒業制作の実データ収集には、オリジナルキャラクターを使うことを推奨する。

## 1. 目的

「テキスト指示 → 画像生成 → VLM による自己診断 → 修正 → 再生成」というループを、身近な対象「ドラえもん」で具体化し、以下を検証する。

1. **評価軸をどう設計するか**（キャラクター特徴の取りこぼしを防ぐ）
2. **ループを可視化する仕組み**（何回回したか、どこで詰まったか）
3. **人間がどこに入るべきか**（完全自動ではなく、人間の判断を残すポイント）

## 2. タスク例

| # | 入力意図（Intent） | 生成物 | 期待する VLM 診断 |
|---|-------------------|--------|------------------|
| 1 | 「ドラえもんが本を読んでいる」 | 青いロボットが本を持っている | 正しく認識。追加修正なし or 表情を追加 |
| 2 | 「ドラえもんが空を飛んでいる」 | 体が赤く、耳がある | ** failure**: 色が青くない、耳がないはず |
| 3 | 「藤子不二雄風のドラえもん」 | 3D レンダリング風 | ** failure**: タッチが原作風ではない |
| 4 | 「ドラえもんの四次元ポケットから道具が出ている」 | ポケットが描かれていない | ** failure**: 四次元ポケットが欠落 |

## 3. 評価軸（Evaluation Axes）

### 3.1 キャラクター構造的特徴（客観的に判定しやすい）

| 軸 | 内容 | 判定方法 | 重み |
|---|------|---------|------|
| `color_blue` | 体色は青白い | 色ヒストグラム + CLIP | 高 |
| `round_body` | 丸い体型 | 輪郭検出 / 円形度 | 高 |
| `no_ears` | 耳がない | 対象検出 | 高 |
| `red_nose` | 赤い鼻 | 色検出 | 中 |
| `white_face` | 白い顔 | 色検出 | 中 |
| `yellow_bell` | 黄色い鈴 | 色検出 | 中 |
| `fourth_d_pocket` | 四次元ポケットがある | VLM caption / 検出 | 中 |
| `whiskers` | ヒゲが6本 | 線検出 | 低〜中 |

### 3.2 スタイル・雰囲気（主観的だが VLM で言語化可能）

| 軸 | 内容 | 判定方法 |
|---|------|---------|
| `fujiko_touch` | 藤子不二雄風のタッチか | VLM / 参照画像との CLIP 類似 |
| `line_art_style` | アニメ的線画か | エッジ検出 + VLM |
| `background_fit` | 背景が意図と合っているか | VLM キャプション + CLIP |
| `expression_match` | 表情がシチュエーションに合っているか | VLM |

### 3.3 全体的品質

| 軸 | 内容 |
|---|------|
| `overall_quality` | 全体的な完成度 |
| `intent_alignment` | ユーザーの自然言語意図との一致 |
| `artifacts` | 崩れ、余分な肢体、不自然な融合 |

## 4. VLM 修正ループ

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│  人間: 意図を入力  "ドラえもんが本を読んでいる"                              │
└──────────────────────────────────┬──────────────────────────────────────────┘
                                   ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  1. 意図解析エージェント                                                     │
│     - キーワード抽出: 主体(ドラえもん), 動作(読む), 対象(本)                 │
│     - 必須構造的特徴を選定: color_blue, round_body, no_ears, fourth_d_pocket │
│     - スタイル要求を選定: fujiko_touch, line_art_style                       │
└──────────────────────────────────┬──────────────────────────────────────────┘
                                   ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  2. 生成エージェント (bpy / SVG)                                             │
│     - ドラえもんの SVG/bpy テンプレートを読み込み                            │
│     - 動作・小道具（本）を反映したパラメータを生成                           │
└──────────────────────────────────┬──────────────────────────────────────────┘
                                   ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  3. VLM 自己診断エージェント                                                 │
│     - 画像を入力に、各評価軸でスコアと理由を出力                             │
│     - 0.5 未満の軸を failure として抽出                                      │
│     - failure → repair instruction（修正指示）を生成                         │
└──────────────────────────────────┬──────────────────────────────────────────┘
                                   ▼
                    ┌────────────────────────┐
                    │  全軸 >= 0.5 ?         │
                    └──────────┬─────────────┘
              YES │                        │ NO
                  ▼                        ▼
┌──────────────────────────┐    ┌─────────────────────────────────────────────┐
│  4a. 合格 → 人間に提示   │    │  4b. 修正エージェント                        │
│     人間が OK/NG を選択  │    │  - repair instruction を bpy/SVG 操作に変換  │
└──────────┬───────────────┘    │  - 例: "体色を青にする" → fill color 変更    │
           │                    └──────────────────────────────────┬──────────┘
    OK     │ NO / 部分修正                                        │
           ▼                                                        ▼
┌──────────────────────────┐                           ┌───────────────────────┐
│ 5. 保存・学習            │ ◄─────────────────────────│  2. 再生成            │
│   - DB に記録            │      （ループ回転 +1）    │   （修正パラメータ）  │
│   - 人間スコアで学習     │                           └───────────────────────┘
└──────────────────────────┘
```

## 5. 人間の操作の余地（Human-in-the-loop）

完全自動ではなく、以下のポイントで人間が入る。

### 5.1 意図入力段階

- 自然言語プロンプトを自由に入力
- 必須特徴の一覧を確認・追加・削除
- スタイル参照画像をアップロード

### 5.2 VLM 診断への同意/訂正

- VLM が出した failure 理由が正しいかを人間が判定
- 誤検出を「無視」マーク → 次回以降その軸の重みを下げる
- 見落としを人間が追加 → 新しい failure を作成

### 5.3 修正指示への承認

- VLM 生成の repair instruction を承認 / 修正 / 却下
- 「耳がない」の修正が「耳を描く」ではなく「耳の痕跡を消す」など、意図に応じた調整

### 5.4 直接編集

- SVG/bpy コードを人間が直接修正
- 修正箇所と理由を DB に記録 → 今後の repair strategy 学習に利用

### 5.5 ペアワイズ比較

- 複数バリエーションを提示
- 人間が「どちらがドラえもんらしいか」を選択
- Bradley-Terry モデルで嗜好を学習

### 5.6 評価軸・重みの調整

- 「今回はタッチより構造的正確性を優先」など、軸の重みを動的に変更
- 長期的に人間の価値観を反映した重みベクトルを更新

## 6. ループ可視化の要件

HTML/Mermaid で以下をリアルタイム表示する。

| 表示項目 | 内容 |
|---------|------|
| **Rotation Counter** | 現在のループ回転数、目標回転数、コスト |
| **Current State** | どの段階（生成 / VLM診断 / 修正 / 人間レビュー）か |
| **Score Radar Chart** | 各評価軸のスコアをレーダーチャートで表示 |
| **Failure Timeline** | 過去の failure と repair instruction の履歴 |
| **Diff View** | 前回画像と今回画像の並べ比べ、修正箇所ハイライト |
| **Human Queue** | 人間の承認待ち項目の一覧 |
| **Cost Meter** | 推定トークン消費、累積コスト、予算残高 |

## 7. 評価軸の重み学習

初期重みは固定だが、人間の選択から更新する。

```text
初期重み: [color_blue=1.0, round_body=1.0, no_ears=1.0, ...]
人間が「耳がない」より「色が違う」を重視した → no_ears 重み下げ、color_blue 重み上げ
→ 次回の VLM 診断で優先軸が変化
```

## 8. コスト設計

| 項目 | コスト要因 | 削減策 |
|------|-----------|--------|
| VLM 診断 | 画像入力トークン | 軽量 VLM / CLIP による事前フィルタ |
| 修正コード生成 | テキスト出力トークン | 修正テンプレートを固定し差分のみ生成 |
| 人間評価 | 人間時間 | ペアワイズ比較（1クリック）を基本にする |
| Blender レンダリング | CPU 時間 | 低解像度プレビュー + 高解像度最終出力 |

## 9. 実装への落とし込み

- `mcp/blender-bpy` に「ドラえもん SVG テンプレート」を追加
- `mcp/evaluator` に各評価軸専用ツールを追加
- `mission/doraemon-vlm-correction.html` でループ可視化
- DB テーブル `auto_evaluations`, `feedback`, `human_evaluations` を活用

## 10. まとめ

ドラえもんの例を通じて、以下を具体化した。

1. **評価軸**: 構造的特徴（客観）＋ スタイル・雰囲気（主観的だが VLM で言語化）
2. **ループ**: 意図解析 → 生成 → VLM 診断 → 修正 → 再生成 → 人間承認 → 学習
3. **人間の余地**: 意図入力、診断同意、修正承認、直接編集、ペアワイズ比較、重み調整

次のステップ：軽量 VLM（Phi-3.5 Vision / LLaVA-OneVision 等）をローカルで動かし、実際の failure/repair instruction 生成を試す。
