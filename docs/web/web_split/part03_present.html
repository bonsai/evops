システムの簡単な説明1 文の定義 + 3 行。聞き手が要った時だけ補足する。

（例）店の日報一覧

（例）入力して検索し、集計してCSVへ

（例）紙とExcel、手作業の二重入力だから

構造の説明（設計モデル）3 層と依存方向だけで 1 分。

30
FIG 3-1
パッケージ構成（発表用の簡略図）
図 3-1　3 層構造　／　矢印は呼び出し方向。上層から下層へしか呼ばない。
なぜ層に分けるか

画面とロジックを分離することで、ロジックだけをテストできる。GUI なしで確認できる。

«interface» の役割

永続化（JSON ／ SQLite）を差し替え可能にし、テストではメモリ実装を使う（依存注入）。

説明の順番

「3 層ある」から「上から下へ呼ぶ」から「domain が核。テスト済み」。これで 60 秒。

発表で触れない：クラス図の属性・操作の細部、シーケンス図のメッセージ番号。 それらは質疑対応（p.19–20 に書いている）。
