アクターの留意点
  • 必ずシステムの外側に存在する。田中さんではなく「○○利用者」という役割で表す。
  • 実在の人物名は使わない。
  • 「時刻」がアクターになるなら ⇔ バッチ処理がある。日時指定の処理も表現する。

境界の判断基準
問い答え
誰が（何が）使うか
どこで責任を切るか
保存データはどこ
UI は内側か外側か

原則：「入力値の検証」と「表示」はシステム内。利用者本人の手作業は外。

講義の事例（酒問屋）

顧客が直接注文する場合 → 境界は「注文を受ける」。
受付係が処理する場合 → 境界は「受付処理」。Swing などで自動化するなら内側。

→ 自分のシステムで同じ検討を 1 度書く。

adomain/record.py — 《entity》
from dataclasses import dataclass
from datetime import datetime

@dataclass
class Record:
    """台帳の 1 項目を表すエンティティ。"""
    _id: int
    _name: str
    _updated: datetime

    def __post_init__(self) -> None:
        self._updated = datetime.now()

    @property
    def name(self) -> str:
        return self._name

    @name.setter
    def name(self, value: str) -> None:
        if not value.strip():
            raise ValueError("名称は必須です")
        self._name = value
bservice/record_service.py — 《control》
from domain.record import Record
from repository.base import RecordRepository

class RecordService:
    """登録・検索のユースケースを実行する。"""
    def __init__(self, repo: RecordRepository) -> None:
        self._repo = repo

    def register(self, name: str) -> Record:
        record = Record(_id=self._repo.next_id(), _name=name)
        self._repo.save(record)
        return record

    def search(self, keyword: str) -> list[Record]:
        records = self._repo.all()
        return [r for r in records
                if keyword in r.name]
