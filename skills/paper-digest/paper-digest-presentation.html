paper-digest

論文を形態に依存しない中間表現に「咀嚼」し、
漫画・動画・漫才・記事へ変換するシステム

MCP Server / Port 8008 / HTTP + stdio

解決したい問題

専門論文は専門外の人にとって「読めない」「伝わらない」

Before

• 「深層残差学習は勾配消失問題を緩和する」
• 専門用語の壁
• 数学的フォーマルな記述
• 読者は研究者のみ

After（目標）

• 「深く学習すれば賢くなるはず…でも深すぎると情報が届かない！→ショートカット道を作ろう」
• 比喩と物語
• 4コマ漫画・アニメ
• 高校生でも理解可能

paper-digest とは

1. Decompose

論文を主張・根拠・制約の「原子知識」に分解

2. Metaphorize

専門用語を高校生レベルの比喩に翻訳

3. Structure

起承転結の物語骨組みに構造化

この3段階で論文は「形態に依存しない中間表現 = DigestedPaper」に変換される

中間表現：DigestedPaper

@dataclass
class DigestedPaper:
    title: str
    summary: str
    atoms: List[AtomicKnowledge]          # 原子知識
    metaphors: List[IntuitiveMetaphor]    # 直感的比喩
    skeleton: NarrativeSkeleton           # 物語構造

@dataclass
class AtomicKnowledge:
    claim: str        # 主張（例: skip connectionは学習を安定化する）
    evidence: str     # 根拠（例: CIFAR-10でエラー率3.57%）
    constraints: str  # 制約（例: 152層以上で有効）

@dataclass
class IntuitiveMetaphor:
    term: str         # 専門用語（例: 勾配消失）
    metaphor: str     # 比喩（例: 伝言ゲームで最後まで伝わらない）
    target_audience: str  # 想定読者レベル（例: 高校生）

物語構造：NarrativeSkeleton

起 (Setup)

常識・前提
「深く学習すれば賢くなるはず」

承 (Conflict)

問題発生・挫折
「深すぎると情報が届かない！伝言ゲーム状態」

転 (Resolution)

解決策・突破
「ショートカット道（skip connection）を作れば届く！」

結 (Punchline)

結論・インパクト
「これでどんどん深く学べる！」

MCP Server 仕様

HTTP モード

• GET /health — 生存確認
• POST /call — ツール呼び出し
• POST /mcp/call — MCP準拠
• Port: 8008

stdio モード

• Claude Desktop / Cline 連携
• python3 server.py --stdio
• JSON-RPC over stdin/stdout

設計パターン：Digestion Sandwich

Input → Output（直接変換）

❌ 問題
• 新しい出力形態ごとにパイプラインを一から構築
• 論文解析の改善が全パイプラインに波及
• A/Bテストに別パイプラインが必要

Input → Digest → Output（本設計）

✅ 解決
• 新しい出力 = Adapter 1つ書くだけ
• 論文解析の改善 = Digestion層のみ修正
• A/Bテスト = Adapter差し替えのみ

なぜ「咀嚼」が効くか

人的な知識伝達に近い

人間が論文を説明するとき、まず「要旨を整理→比喩を探す→話の流れを作る」を無意識に行う。paper-digest はそのプロセスをアルゴリズム化した。

形態に依存しない

Manga・YouTube・Manzai・Note は表現形態が異なるが、根幹の「知識+比喩+物語」は共通。中間表現を挟むことで、増殖する出力形態に追従できる。

品質が蓄積する

Metaphor データベースが蓄積されると、同一用語の翻訳が自動的に改善される。システムが使うほど賢くなる。

教育文化との親和性

「比喩で理解する」は日本の教育文化に根ざしたアプローチ。「わかりやすい説明」の自動化。
